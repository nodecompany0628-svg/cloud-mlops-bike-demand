# 재실행, 권한, 비용, 자원 정리

진행 상태: 권한 범위와 비용 제한 방법은 정했다. 새 폴더 재실행(클라우드 포함), 실제 청구액 확인, 자원 정리 후 상태 조회는 AWS에서 실행한 뒤 채운다.

## 1. 새 폴더에서 다시 실행

실행 전이다. 절차는 다음과 같다.

1. 공개 저장소를 새 폴더에 `git clone`
2. README의 설치 명령
3. `python -m pytest -q` (zip을 아직 만들지 않았으므로 zip이 필요한 1개는 건너뛴다)
4. `python -m bikeml --profile <프로필> run all`
5. 결과를 원래 결과와 비교: 지표(MAE 등)와 클라우드 응답. 같은 OS와 라이브러리면 모델 sha256도 같아야 한다

## 2. 접근 권한

| 주체 | 대상 | 권한 |
|---|---|---|
| 운영자 (배포와 정리를 실행하는 사람) | 이 과제의 버킷, 역할, 함수, 로그 그룹 | [docs/iam/operator-policy.json](iam/operator-policy.json). 자원 이름을 `bike-demand-*`로 좁혔다. 버킷 목록 조회(`s3:ListAllMyBuckets`)와 로그 그룹 목록 조회만 계정 전체가 대상이다. 역할을 만들거나 역할 정책을 바꾸는 권한은 권한 경계 `bike-demand-predict-boundary`가 붙은 역할에만 쓸 수 있다 |
| Lambda 실행 역할 `bike-demand-predict-role` | 자기 로그 그룹, 이 과제 버킷(`bike-demand-mlops-*`)의 `models/*` | 로그 쓰기, `s3:GetObject`, `s3:GetObjectVersion`만. 권한 경계 `bike-demand-predict-boundary`가 같은 범위로 상한을 건다 |
| 호출하는 사람 | 함수 `bike-demand-predict`의 `live` 별칭 | `lambda:InvokeFunction`. 공개 주소는 만들지 않는다 |

- 버킷은 공개 접근 차단 4가지를 모두 켠다.
- `iam:PassRole`은 Lambda에 넘길 때만 허용한다(`iam:PassedToService` 조건).
- 자격 증명은 로컬 AWS 프로필(`~/.aws/credentials`)에만 두고 코드, 설정, 기록, Git에는 넣지 않는다. 실행할 때 `--profile`이나 `AWS_PROFILE`로 고른다. 지정하지 않으면 클라우드 단계는 AWS에 접속하기 전에 멈춘다. 프로필이 지정되어 있으면 프로필을 쓴다. 프로필 없이 환경 변수의 키를 쓰려면 `BIKEML_USE_ENV_CREDENTIALS=1`을 함께 지정해야 하고, 그때는 환경 변수의 키만 쓴다.
- 루트 계정 키보다 위 정책을 붙인 IAM 사용자 키를 쓰는 편이 안전하다.
- 기존 자원이나 계정 보안 설정은 바꾸지 않는다. 새로 만드는 자원(버킷, IAM 역할, Lambda 함수, 로그 그룹, 도구가 만든 권한 경계 정책)에만 태그 `project=cloud-mlops-assignment`, `owner=student`를 붙인다. 이름이 같아도 이 태그가 없는 버킷, IAM 역할, Lambda 함수, 로그 그룹은 건드리지 않는다. 배포와 release는 그 자리에서 멈추고, 정리는 그 자원을 건너뛰어 `not_ours`에 적고 이 과제의 자원은 모두 지운다. 태그 없는 같은 이름의 함수가 이 과제의 실행 역할을 쓰고 있으면 역할은 남기고 실패로 기록한다. 설정의 `cloud.bucket`에 남의 버킷을 적어 두었다면 설정에서 지운다. 예외는 태그도 객체도 없는 빈 버킷 중, 이 도구의 이름 형식(`bike-demand-mlops-<리전>-<16진수 8자리>`)이거나 이 도구가 그 이름으로 버킷을 만들려고 한 기록이 있는 버킷뿐이다. 버킷을 만든 직후 태그를 붙이기 전에 멈춘 경우로 보고, 배포는 이어받고 정리는 지운다.

## 3. 비용이 생기는 자원과 제한 방법

서울 리전 단가 (AWS 가격 정보, 2026-11 확인)

| 자원 | 단가 | 예상 사용량 | 제한 방법 |
|---|---|---|---|
| Lambda | 요청 100만 건당 0.20달러, GB-초당 0.0000166667달러 (x86). 초기화 시간도 과금 | 검사와 평가 한 번에 19회 호출(smoke 13회, cloud-eval 6회). 역할을 새로 만든 배포에서는 smoke 전 권한 확인 1~6회가 더해진다. 수십 GB-초 | 예약 동시성 2(계정 할당량이 낮으면 거절되어 적용되지 않을 수 있고, 그 결과는 `deploy.json`에 남는다), 제한 시간 30초, 요청당 최대 1,000건 |
| S3 | 저장 GB-월당 0.025달러, PUT 1,000건당 0.0045달러 | 패키지 64MB × 배포 횟수, 모델 0.7MB × 학습한 모델 수 | 수명 주기 규칙(`packages/`는 30일 뒤 만료되고 이전 버전은 1일 뒤 삭제, `models/`의 이전 버전은 30일 뒤 삭제. 두 규칙의 대상 경로는 겹치지 않는다), 끝나면 버킷 삭제 |
| CloudWatch Logs | 수집 GB당 0.76달러, 저장 GB-월당 0.0314달러 | 수 KB에서 수백 KB | 보관 7일, 끝나면 로그 그룹 삭제 |
| IAM | 무료 | | |

Lambda 무료 사용량(매월 요청 100만 건, 40만 GB-초)을 빼지 않고 계산해도 100 GB-초 약 0.0017달러, S3 0.2GB 5일 약 0.0008달러, 로그는 그보다 적어 합계 0.01달러 미만이다. 실제 청구액은 실행 후 확인해서 적는다.

AWS Budgets 경보는 알림 받을 이메일이 필요해서 스크립트로 만들지 않았다. 콘솔에서 월 1달러 예산 경보를 걸어 두는 것을 권장한다.

## 4. 자원 정리와 정리 후 상태

실행 전이다. `python -m bikeml --profile <프로필> cleanup`이 하는 일은 다음과 같다.

1. 정리할 리전과 버킷을 정한다. 규칙은 [cloud.md](cloud.md) 2절에 있다(지금 리전, 상태 파일, 실행 기록, 배포 기록, 버킷 이름). 그리고 정리 전 상태를 조회한다.
2. 리전마다 Lambda 함수(모든 버전과 별칭 포함), 로그 그룹, S3 버킷(이름이 맞는 버킷이 여러 개면 모두, 모든 객체 버전과 삭제 표시 먼저)을 삭제한다. 이 과제의 지역 자원이 모두 지워졌을 때만 마지막으로 IAM 역할(인라인 정책 먼저)을 삭제하고, 역할이 지워졌으면 이 도구가 만든 권한 경계 정책도 지운다(루트나 관리자 키일 때. 운영자 키에는 정책 삭제 권한이 없어 `kept`로 남긴다). 경계 정책 삭제가 `DeleteConflict`로 실패하면(역할 삭제가 아직 반영되지 않았거나, 기본 버전이 아닌 이전 버전이 남은 경우) 이전 버전을 지우고 3초 간격으로 최대 10번 시도한다. 관리자가 만든 경계 정책(태그 없음)은 남긴다. IAM 정책은 비용이 없다. 이 과제의 지역 자원이 하나라도 남으면 그 자원이 역할을 쓸 수 있으므로 역할을 남긴다. 이 과제의 태그가 없는 자원은 지우지 않고 `not_ours`에 기록한다.
3. 다시 조회해서 이 과제의 자원(함수, 로그 그룹, 버킷, 역할)이 모두 없는지 확인한다. 태그 없는 같은 이름의 자원은 `not_ours`에 따로 적는다. 역할까지 지운 경우에는 IAM 반영이 늦을 수 있어 3초 간격으로 최대 10번 다시 본다. 일부러 남긴 자원이 있으면 기다리지 않는다.
4. 이 과제의 자원이 하나라도 남거나, 권한 오류 등으로 상태를 확인하지 못하거나, 지우다가 오류가 난 자원이 있거나, 접속하지 못한 리전이 있거나, 실행 기록에 읽을 수 없는 줄이 있으면 실패로 기록하고, 오류 메시지에 이유를 모두 적는다. 켜지 않은 리전(인증 오류)은 건너뛰지만, 이 계정의 자원이 있다고 알려진 리전이면 인증 오류여도 실패다. 실행 기록에 읽을 수 없는 줄이 있으면 찾은 자원은 지우되 역할은 남긴다. 설정의 이름을 바꾸기 전에 배포하고 정리하지 않은 기록이 있으면 실패로 기록한다(지금 이름으로 배포한 기록이 없으면 아무것도 지우지 않는다). 다 지웠더라도 다른 계정으로 배포한 기록이 `.state/regions.json`에 남아 있으면 실패로 기록하고 그 계정의 프로필로 다시 실행하라고 알린다. 그 계정을 더 이상 쓸 수 없으면 `.state/regions.json`에서 그 항목을 지운다. 이 계정에서 쓸 수 없는 리전 때문에 계속 실패하면 `--ignore-region`으로 그 리전을 뺀다([cloud.md](cloud.md) 2절).
5. 결과는 성공하면 `results/cloud/cleanup.json`, 실패로 기록되면 `results/failed/<run_id>_cleanup/results/cloud/cleanup.json`에 남는다. 다른 계정의 기록 때문에 실패로 기록된 경우에도 이 계정의 자원 삭제 결과는 그 파일에 있다. AWS 접속 단계에서 실패하면 아무것도 지우지 않은 채 `error.txt`만 남는다. 지우는 도중 예상하지 못한 오류로 멈추면 그때까지의 삭제 결과가 `interrupted`와 함께 결과 파일에 남는다.
