# 재실행, 권한, 비용, 자원 정리

> **진행 상태**: 권한 범위와 비용 제한 방법은 정했습니다. 새 폴더 재실행, 실제 비용 확인, 자원 정리 후 상태 조회는 **AWS 실행 뒤에 채웁니다.**

## 1. 새 폴더에서 다시 실행

⏳ **클라우드 포함 재실행은 실행 전**.
절차: 공개 저장소를 새 폴더에 `git clone` → README의 설치 명령 → `python -m pytest -q` → `python -m bikeml run all` → 결과를 원래 결과와 비교(모델 sha256, MAE, 클라우드 응답).

## 2. 접근 권한

| 주체 | 대상 | 권한 |
|---|---|---|
| 운영자(배포·정리를 실행하는 사람) | 이 과제의 버킷, 역할, 함수, 로그 그룹 | [docs/iam/operator-policy.json](iam/operator-policy.json). 이름이 `bike-demand-*`인 자원으로 범위를 좁힘 |
| Lambda 실행 역할 `bike-demand-predict-role` | 자기 로그 그룹, 버킷의 `models/*` | 로그 쓰기, `s3:GetObject`만 |
| 호출하는 사람 | 함수 `bike-demand-predict` | `lambda:InvokeFunction`. 공개 URL은 만들지 않음 |

- 버킷은 공개 접근 차단(4가지 모두)을 켭니다.
- 자격 증명은 로컬 AWS 프로필(`~/.aws/credentials`)에만 두고, 코드·설정·기록·Git에는 넣지 않습니다. 실행할 때 `--profile` 또는 `AWS_PROFILE`로 고릅니다.
- 루트 계정 키보다 위 정책을 붙인 IAM 사용자 키를 권장합니다.
- 기존 자원이나 계정 보안 설정은 바꾸지 않습니다. 새로 만드는 자원 4개에만 태그 `project=cloud-mlops-assignment`를 붙입니다.

## 3. 비용이 생기는 자원과 제한 방법

| 자원 | 과금 요소 | 예상 사용량 | 제한 방법 |
|---|---|---|---|
| Lambda | 요청 수, 실행 시간 × 메모리(GB-초) | 검사·평가 한 번에 약 20회 호출, 수십 GB-초 | 예약 동시성 2, 제한 시간 30초, 요청당 최대 1,000건 |
| S3 | 저장 용량, 요청 수 | 패키지 53MB × 배포 횟수 + 모델 0.7MB | 수명 주기 규칙(`packages/` 30일, 이전 버전 1~30일 뒤 삭제), 끝나면 버킷 삭제 |
| CloudWatch Logs | 수집량, 저장량 | 수 KB~수백 KB | 보관 7일, 끝나면 로그 그룹 삭제 |
| IAM | 무료 | — | — |

예상 비용은 1달러에 한참 못 미칩니다(Lambda 무료 사용량은 매월 요청 100만 건, 40만 GB-초). 실제 청구액은 실행 후 확인해서 적습니다.
AWS Budgets 경보는 알림 받을 이메일이 필요해서 스크립트로 만들지 않았습니다. 콘솔에서 월 1달러 예산 경보를 거는 것을 권장합니다.

## 4. 자원 정리와 정리 후 상태

⏳ **실행 전**. `python -m bikeml cleanup`이 하는 일:

1. 정리 전 상태 조회
2. Lambda 함수(모든 버전 포함) → 로그 그룹 → IAM 역할(인라인 정책 먼저) → S3 버킷(모든 객체 버전과 삭제 표시 먼저) 순서로 삭제
3. 다시 조회해서 4개 자원이 모두 "없음"인지 확인. 하나라도 남으면 실패로 기록
4. 결과: `results/cloud/cleanup.json`

## 5. 보관하는 자료

| 자료 | 위치 | 이유 |
|---|---|---|
| 코드, 원자료, 정리한 자료, 모델, 평가·실행 기록 | 공개 GitHub 저장소 | 제출물. 데이터는 CC BY 4.0이라 재배포 가능 |
| 배포 패키지 zip | 저장하지 않음 (`build/`는 Git 제외) | `python -m bikeml run package`로 다시 만들 수 있음 |
| 클라우드 자원 | 남기지 않을 계획 | 평가는 저장소 기록으로 하므로 계속 켜 둘 필요가 없음 |
