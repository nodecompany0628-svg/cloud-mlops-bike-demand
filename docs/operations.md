# 재실행, 권한, 비용, 자원 정리

진행 상태: 권한 범위와 비용 제한 방법은 정했다. 새 폴더 재실행(클라우드 포함), 실제 청구액 확인, 자원 정리 후 상태 조회는 AWS에서 실행한 뒤 채운다.

## 1. 새 폴더에서 다시 실행

실행 전이다. 절차는 다음과 같다.

1. 공개 저장소를 새 폴더에 `git clone`
2. README의 설치 명령
3. `python -m pytest -q`
4. `python -m bikeml --profile <프로필> run all`
5. 결과를 원래 결과와 비교: 모델 sha256, MAE, 클라우드 응답

## 2. 접근 권한

| 주체 | 대상 | 권한 |
|---|---|---|
| 운영자 (배포와 정리를 실행하는 사람) | 이 과제의 버킷, 역할, 함수, 로그 그룹 | [docs/iam/operator-policy.json](iam/operator-policy.json). 자원 이름을 `bike-demand-*`로 좁혔다. 버킷 목록 조회(`s3:ListAllMyBuckets`)와 로그 그룹 목록 조회만 계정 전체가 대상이다 |
| Lambda 실행 역할 `bike-demand-predict-role` | 자기 로그 그룹, 버킷의 `models/*` | 로그 쓰기, `s3:GetObject`, `s3:GetObjectVersion`만 |
| 호출하는 사람 | 함수 `bike-demand-predict`의 `live` 별칭 | `lambda:InvokeFunction`. 공개 주소는 만들지 않는다 |

- 버킷은 공개 접근 차단 4가지를 모두 켠다.
- `iam:PassRole`은 Lambda에 넘길 때만 허용한다(`iam:PassedToService` 조건).
- 자격 증명은 로컬 AWS 프로필(`~/.aws/credentials`)에만 두고 코드, 설정, 기록, Git에는 넣지 않는다. 실행할 때 `--profile`이나 `AWS_PROFILE`로 고른다. 지정하지 않으면 클라우드 단계는 AWS에 접속하기 전에 멈춘다. 환경 변수의 키를 쓰려면 `BIKEML_USE_ENV_CREDENTIALS=1`을 함께 지정해야 하고, 그때는 환경 변수의 키만 쓴다.
- 루트 계정 키보다 위 정책을 붙인 IAM 사용자 키를 쓰는 편이 안전하다.
- 기존 자원이나 계정 보안 설정은 바꾸지 않는다. 새로 만드는 자원 4개에만 태그 `project=cloud-mlops-assignment`, `owner=student`를 붙인다. 이름이 같아도 이 태그가 없는 버킷, IAM 역할, Lambda 함수, 로그 그룹은 배포, release, 정리에서 건드리지 않고 멈춘다. 예외는 이 도구가 만든 이름 형식(`bike-demand-mlops-<리전>-<16진수 8자리>`)이고 태그도 객체도 없는 빈 버킷 하나뿐이다. 버킷을 만든 직후 태그를 붙이기 전에 멈춘 경우로 보고, 배포는 이어받고 정리는 지운다.

## 3. 비용이 생기는 자원과 제한 방법

서울 리전 단가 (AWS 가격 정보, 2026-11 확인)

| 자원 | 단가 | 예상 사용량 | 제한 방법 |
|---|---|---|---|
| Lambda | 요청 100만 건당 0.20달러, GB-초당 0.0000166667달러 (x86). 초기화 시간도 과금 | 검사와 평가 한 번에 19회 호출(smoke 13회, cloud-eval 6회), 수십 GB-초 | 예약 동시성 2, 제한 시간 30초, 요청당 최대 1,000건 |
| S3 | 저장 GB-월당 0.025달러, PUT 1,000건당 0.0045달러 | 패키지 64MB × 배포 횟수, 모델 0.7MB × 학습한 모델 수 | 수명 주기 규칙(`packages/`는 30일 뒤 만료, 이전 버전은 1~30일 뒤 삭제), 끝나면 버킷 삭제 |
| CloudWatch Logs | 수집 GB당 0.76달러, 저장 GB-월당 0.0314달러 | 수 KB에서 수백 KB | 보관 7일, 끝나면 로그 그룹 삭제 |
| IAM | 무료 | | |

Lambda 무료 사용량(매월 요청 100만 건, 40만 GB-초)을 빼지 않고 계산해도 100 GB-초 약 0.0017달러, S3 0.2GB 5일 약 0.0008달러, 로그는 그보다 적어 합계 0.01달러 미만이다. 실제 청구액은 실행 후 확인해서 적는다.

AWS Budgets 경보는 알림 받을 이메일이 필요해서 스크립트로 만들지 않았다. 콘솔에서 월 1달러 예산 경보를 걸어 두는 것을 권장한다.

## 4. 자원 정리와 정리 후 상태

실행 전이다. `python -m bikeml --profile <프로필> cleanup`이 하는 일은 다음과 같다.

1. 정리할 리전을 정한다. 지금 리전, 이 PC에서 같은 계정으로 배포를 시작했던 리전(`.state/regions.json`), 배포 기록(`results/cloud/deploy.json`, `deploy_override.json`)의 리전을 모두 포함한다. 그리고 정리 전 상태를 조회한다.
2. 리전마다 Lambda 함수(모든 버전과 별칭 포함), 로그 그룹, S3 버킷(모든 객체 버전과 삭제 표시 먼저)을 삭제하고, 마지막으로 IAM 역할(인라인 정책 먼저)을 삭제한다. 이 과제의 태그가 없는 자원은 지우지 않고 남은 자원으로 기록한다.
3. 다시 조회해서 4개 자원이 모두 없는지 확인한다. IAM은 반영이 늦을 수 있어 3초 간격으로 최대 10번 다시 본다.
4. 하나라도 남거나, 권한 오류 등으로 상태를 확인하지 못하면 실패로 기록한다. 다 지웠더라도 다른 계정으로 배포한 기록이 `.state/regions.json`에 남아 있으면 실패로 기록하고 그 계정의 프로필로 다시 실행하라고 알린다.
5. 결과는 `results/cloud/cleanup.json`에 남는다.
